# AGENTS.md

## Stack
- Laravel 13 (`laravel/framework` ^13.8), PHP ^8.3
- **Auth is JWT** via `php-open-source-saver/jwt-auth` (^2.9). Sanctum was removed — do not reintroduce session/cookie API auth.
- Fortify 1.37 is used only for its actions (`CreateNewUser`, `ResetUserPassword`) and the `VerifyEmailResponse` binding. `Fortify::routes()` is never called, so Fortify registers **no routes** — its feature flags (`Features::registration()`, `resetPasswords()`) are routing-inert; all auth endpoints are the custom ones in `routes/api.php`. `laravel/passkeys` comes in as a Fortify dep (passkeys/2FA commented out in `config/fortify.php`). Socialite 5.29 present.
- Local dev DB is **Supabase Postgres** (`.env` has `DB_CONNECTION=pgsql`) using the **IPv4 pooler** host (`aws-0-eu-north-1.pooler.supabase.com`, user `postgres.<ref>`) — the direct host is IPv6-only and fails on many networks. `.env.example` still defaults to sqlite; `database/database.sqlite` exists but is unused.
- Frontend: sibling SPA at `../frontend` (React 19 + Vite, has its own AGENTS.md). It stores the JWT in `localStorage`, sends `Authorization: Bearer`, no cookies/CSRF. CORS `supports_credentials=false`; `allowed_origins` (config/cors.php) = `FRONTEND_URL` + `http://127.0.0.1:5173`, deduped — keep both: Vite binds only `::1:5173` while `php artisan serve` binds IPv4 `127.0.0.1:8000`, and the browser's `localhost` falls back between them.

## Commands (composer scripts)
- `composer setup` — install, copy `.env`, `key:generate`, `migrate --force`, build assets
- `composer dev` — `php artisan serve` + queue worker + `pail` + Vite concurrently
- `composer test` — runs `config:clear` first (phpunit env overrides are inert if config is cached), then `artisan test`
- `php artisan test --filter=<name>` — single test
- `./vendor/bin/pint` — Laravel default preset, no `pint.json`

## DB & tests
- `phpunit.xml` forces all tests onto in-memory SQLite (`DB_CONNECTION=sqlite`, `:memory:`, `QUEUE_CONNECTION=sync`). Feature tests never touch Supabase.
- Local `QUEUE_CONNECTION=database` — verification emails only send while `composer dev`'s queue worker runs.

## API & auth conventions
- `routes/api.php`: public throttled `POST /api/register` + `/api/login`; then `auth:api` group: `GET /api/user`, `PUT /api/user` (update name/email), `PUT /api/user/password` (change password), `DELETE /api/user` (account deletion), `POST /api/logout`, `POST /api/email/verification-notification`, `GET /api/gym`, `PUT /api/gym`. Guard `api` → driver `jwt` (`config/auth.php`).
- JWT: HS256, `JWT_TTL=10080` (7 days). **No refresh endpoint** by design.
- Rate limiters in `app/Providers/FortifyServiceProvider.php`: login 5/min, register 5/min, two-factor 5/min, passkeys 10/min.
- Email verification is **custom and stateless**: `GET /email/verify/{id}/{hash}` in `routes/web.php` → `App\Http\Controllers\Auth\EmailVerificationController`, middleware `['signed','throttle:6,1']`, name `verification.verify`. It marks verified and redirects to `FRONTEND_URL/email-verified` (204 for JSON). `Features::emailVerification()` is disabled in `config/fortify.php` so Fortify does NOT register its `auth:web`-gated verify route (that was the bug where links bounced to login).
- Verification email is sent via `Registered` → `SendEmailVerificationNotification` listener in `AppServiceProvider`.
- Mail transport is **Resend** (`MAIL_MAILER=resend`, `RESEND_API_KEY` in `.env`). Default `MAIL_FROM_ADDRESS` is `onboarding@resend.dev`, which Resend only lets deliver to the account owner's own verified address — other recipients get nothing until a verified sending domain is configured (see git log 7361df9).
- Signed links are host-bound: `APP_URL` must match the host users actually click, or verify links 403. Production `APP_URL` must be the exact Render backend URL.
- `bootstrap/app.php` sets `redirectGuestsTo(FRONTEND_URL.'/login')`. This overrides Laravel 13's default `route('login')` — without it, unauthenticated non-JSON requests throw `RouteNotFoundException` (there is no `login` route).
- JSON error rendering is enabled only for `api/*` paths or `expectsJson()` (`shouldRenderJsonWhen` in `bootstrap/app.php`).

## Domain model (gym management)
- `routes/api.php` `auth:api` group exposes dashboard endpoints (gym-scoped): `GET/POST/PUT/DELETE /members` (CRUD accepts the frontend shape: `name` is split to `first_name`/`last_name`, `membership{plan,price,started_at,ends_at}` maps to the latest `MemberSubscription`, which is created/updated in the same call), `GET /staff`, `GET /equipment`, `GET /equipment/repairs`, `GET /checkins`, `POST /checkins`, `POST /checkins/{id}/check-out`, `GET /finances/overview?period=this_week|this_month|last_3_months|last_6_months|this_year`. Frontend consumes these via `frontend/src/lib/dashboardApi.js`; resources in `app/Http/Resources` are shaped to match the frontend mocks.
- Dashboard home is **per-section, never batched**: `DashboardController` (`GET /api/dashboard/overview|insights|operations|finances`, each one request per section) returns ready-made aggregates the section panels render — overview counts (member/staff/equipment/check-in), insights (month revenue, avg, growth, `membershipRevenue[{plan,value}]`, `rosterDonut[{label,value}]`, last 5 check-ins), operations (payroll, last 5 payslips, equipment counts, last 5 repairs), finances (month rev/exp/net/margin + 6-month `revExpData`). No endpoint returns another section's data. Colors are a frontend concern (`frontend/src/lib/finances.js`).
- Schema graph (all `cascadeOnDelete` from user down): `User` → one `UserSubscription` + one `Gym`; `Gym` → `Staff` (→ `Payslip`), `Member` (→ `MemberSubscription` → `Payment`, → `Checkin`), `Equipment` (→ `PurchaseBill`, `RepairBill`). `member_subscriptions.ends_at` is **nullable** (Pay-as-you-go); `checkins.check_out` is nullable (null = member currently inside).
- Backed string enums in `app/Enums` mirror DB `enum` columns: `SubscriptionPlan` (`free_trial|basic|pro|enterprise`), `EquipmentStatus` (`available|maintenance|broken`), `MemberStatus` (`active|frozen|expired`), `StaffStatus` (`active|on_leave|departed`), `GymStatus` (`active|inactive`), `PaymentStatus` (`paid|pending|failed`). `payments`/`payslips` also have a `method` string (default `Card`). Laravel emits enum CHECK constraints on SQLite too, not just pgsql — except the `payslips.month` range CHECK, which the migration adds only when the driver is `pgsql`.
- Check-in guard: `POST /api/checkins` 422s unless the member has an active subscription (latest `MemberSubscription` `starts_at <= today` and `ends_at` null or `>= today`) and no open check-in today. `checkOut` 422s if already checked out, 404 for another gym's check-in.
- Money is stored as decimal strings (tests assert `'49.99'`), not floats. API resources return floats/ints (rounded) to match the frontend mocks; `FinanceOverviewService` returns a monthly series ending at the current month.
- **Dashboard query budget**: `FinanceOverviewService::monthlyOverview()` is cached 5 min per gym+window in the cache store (key `finance_overview:{gym_id}:{monthCount}`) and rebuilt from ~5 joined queries; `MemberController` flush the gym key on store/update/destroy, `DashboardSeeder` does `Cache::flush()`. `DashboardController` fetches all scoped status columns in one `get(['status'])` per entity (enum casts preserved) — do not reintroduce per-status `where()->count()` loops. `GET /api/equipment/payments` does not exist (404); the frontend `usePrefetchDashboardModules` no longer prefetches it, and `EquipmentPage.jsx` no longer queries it either — the `dashboardApi.equipment.payments` method is dead code, and in live mode the page renders an empty payments list (`isLive ? [] : mockPayments`).
- Dev seed: `DB_SEED_USER=you@example.com php artisan db:seed --class=DashboardSeeder --force` (idempotent, bulk-inserts ~1500 rows so it's fast even over the Supabase pooler). `DB_SEED_USER` is the email of the account the demo gym/data is attached to; without it the seeder defaults to creating/using `gym-owner@lean.local` / `password`. Existing target accounts are never password-rewritten (only brand-new ones get `/ password`), and when the target isn't the default owner the old owner account is deleted. Seeder wipes only the target gym's domain rows on re-run.
- `tests/Feature/SchemaRelationshipsTest.php` is the schema-contract test (full graph, cascade delete, uniqueness, constraints) — keep it green when touching migrations. `tests/Feature/AuthTest.php` covers the JWT flow. `tests/Feature/DashboardApiTest.php` covers the dashboard endpoints, shapes, scoping, and check-in guard.

## Deploy (Render + Docker)
- `Dockerfile` is intentionally minimal: single-stage `php:8.4-cli-alpine` + `pdo_pgsql` + opcache (enabled, `opcache.enable_cli=1`), runs `php artisan migrate --force` then `php artisan serve --no-reload` with `PHP_CLI_SERVER_WORKERS=4` (the built-in server forks 4 workers on Linux; Laravel honors the env only with `--no-reload`). No nginx, no queue worker, no healthcheck → set `QUEUE_CONNECTION=sync` on Render. NOTE: prod runs the SAME built-in server as dev (single process family, opcache enabled) — it is NOT php-fpm, so prod still serializes per worker and benefits from opcache being on.
- Health check endpoint: `GET /up` (checks DB connectivity). Set Render health check path to `/up`.
- `.dockerignore` excludes `.env`, `vendor/`, `node_modules/`; Render supplies all env vars itself: `APP_KEY`, `JWT_SECRET`, `JWT_TTL`, `DB_*` (pooler creds), `FRONTEND_URL`, `APP_URL`, `APP_DEBUG=false`, `APP_ENV=production`, `QUEUE_CONNECTION=sync`.

## Repo notes
- `.env`, `vendor/`, `node_modules/` gitignored; `.env` exists locally with real Supabase/JWT/Resend creds.
- No CI, no `opencode.json`. Only seeder is `Database\Seeders\DashboardSeeder` (see Domain model).
- Repo-local OpenCode skills under `.opencode/skills/` (`laravel-expert`, `php-pro`, `api-*`, `database-*`, security) — load the matching skill before API/DB/security work.
- **Dev latency floor**: with `php artisan serve` on Windows and **no opcache in the CLI** (`opcache.enable_cli=0`), every request re-compiles the framework → ~1.5 s per-request floor regardless of query count (a 404 is ~0.4 s; a 1-query endpoint is ~1.5-2 s). Supabase pooler round-trips are ~250 ms; a fresh TLS connection can be ~1 s. Persistent PDO connections (`config/database.php` `options => [PDO::ATTR_PERSISTENT => true]`) were tried and **reverted**: `ATTR_PERSISTENT` confirmed active, but the HTTP floor was unchanged, so the cost is boot/compile, not connection setup (and persistent + PgBouncer transaction pooler adds prepared-statement risk). To actually cut the floor locally: `opcache.enable_cli=1` in php.ini. Prod is the same built-in server but has opcache on and 4 forked workers (see Deploy), so the per-request compile floor is gone there; only the single-threaded serialization (per worker) and ~250 ms pooler round-trips remain.
- **`php artisan serve` is single-threaded + can double-print lines on Windows**: the dashboard fires its section requests in parallel (`DashboardPage`), and the built-in server serializes them — later requests queue behind earlier ones. That queue wait is real wall time: it shows up in the browser Network tab (Network time ≈ server processing + queue wait) and makes the tail requests feel slow, but it is NOT duplicate requests. Verified via in-app request logging (one `http-request` entry per endpoint) and a parallel-load repro (4× `/up` → client totals 2.7–5.4 s vs serve-logged 2–4 s). Under real-browser keep-alive traffic, the serve terminal also prints a spurious fast line (~500 ms) per request alongside the real one — a Windows `php -S` lifecycle-logging/`ServeCommand` artifact that does NOT reach Laravel (the in-app logger never sees it) and does not reproduce with scripted clients. Ground truth for "is it really hitting the app": browser DevTools or an in-app middleware/log, not the serve terminal. Prod is unaffected (4 forked workers on Render, see Deploy).
